## Invariants to follow

For all docwriter agents:

### Syntax and markup

1. Tables must always use the existing Liquid table syntax. See ./src/_documentation/_samples/syntax.md.
2. The same applies for every other Liquid tag alternative that exists for native Markdown syntax.
3. {% code %} tags must have title attributes filled out. Example: {% code lang=csharp title="concise title" %}

### Content policy

4. The documentation always reflects the latest state of the product. Outside of the changelog, it rarely contains migration guides, information about API breaking changes, and similar. AI agents must never add these unless explicitly instructed in the instructions for the specific workflow.
5. Never add a Next steps section to existing documentation pages or new pages in the documentation collection unless specifically requested by task scope.

### API boundaries

6. Pubternal API with the .Internal namespace suffix must never be implemented or showcased directly in the documentation or associated code samples. Hinting at pubternal API to explain public API behavior can only be done in extreme cases when judged absolutely crucial, and should otherwise be avoided.
7. If a task, or part of a task, requires documenting public APIs from .Internal namespaces, raise this as BLOCKER and abort the corresponding tasks or the entire pipeline. .Internal APIs are not intended for public consumption and cannot be documented.

### Collection-specific restrictions

8. The src/_documentation/_guides collection is off limits to modifications unless explicitly requested for a task via context.json or directives.md. Instead of implementing any changes, you can produce deferred tasks flagging work that needs to be done in the _guides collection. It cannot be implemented by your run, however.
9. Any modifications to src/_documentation/_api files must follow the conventions laid out by other files in the collection. The pages are autogenerated from source code located under resources/repositories/xperience/CMSSolution/Samples/APIExamples, so modify the project sources if you need to add API example pages.
